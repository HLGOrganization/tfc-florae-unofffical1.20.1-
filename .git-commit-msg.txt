fix(data): point wood recipes at the tags this mod actually defines

The ported recipes asked for tfc:<wood>_logs - TFC's per-species log tag - but
those species are this mod's own woods, and TFC has no tag for them.  Every plank
/ support / lumber / log-wall recipe for 63 species therefore required a
non-existent tag and could never match.  This mod does ship
tfcflorae:<wood>_logs for all 66 species (log + wood + stripped_log +
stripped_wood), so 126 recipe files now reference those.

Same for bamboo: tfc:all_bamboo_logs never existed; added
tfcflorae:all_bamboo_logs (8 values = the four bamboo species' log and
stripped_log) and rewired the 3 bamboo recipes.

Checked the tags the user suspected:
- minecraft:slabs: 387 values, 171 of ours, zero ids whose blockstate is missing;
  the other 216 entries are TFC's own slabs, which are valid - no tag failure.
- tfc:plants/kelp: TFC 1.20 does not define this tag at all (it only has
  tfc:plants), so nothing of ours can be breaking it, and nothing references it.
- full sweep of every "tag" reference in data/: after this change the only
  unresolved ones are forge:feathers and minecraft:cluster_max_harvestables,
  which Forge and vanilla provide.

tools/inject_data_pack.py now replaces the whole data/ section instead of tags
only (recipes have to travel with tags).  Verified against the pre-injection jar:
24335 data files before and after, 0 lost, 0 gained.
